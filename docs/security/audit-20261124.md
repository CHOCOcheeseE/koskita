# Audit Keamanan KosKita (Hendra, Security)

Tanggal: 24 November 2026
Lingkup: `apps/backend/src` (Eko) dan `apps/mobile/src` (Dimas), termasuk perbaikan BUG-04.

## Keputusan: LOLOS

Tidak ada temuan **kritis** atau **tinggi**. Ada 2 temuan **sedang** dan beberapa **rendah/info**. Semuanya sebaiknya dibereskan di iterasi berikutnya, tapi tidak memblokir.

## Yang sudah aman (dicek langsung di kode)

- **Password**: bcrypt (bcryptjs) cost 10, batas 72 byte di register dan login, ada dummy hash supaya waktu respons login sama untuk email yang tidak terdaftar (anti user-enumeration lewat timing). Pesan error login generik.
- **JWT**: rahasia dari env, wajib minimal 32 karakter (`config/env.ts`). Algoritma dikunci `HS256` untuk sign dan verify. Payload dicek `typ: 'access'` dan `sub` string. Access token 15 menit.
- **Refresh token**: 32 byte acak (`randomBytes`), disimpan sebagai hash SHA-256, sekali pakai (rotasi), dan `updateMany` bersyarat mencegah dua request bersamaan sama-sama lolos. Logout me-revoke refresh token milik user itu saja (`userId` ikut di `where`).
- **Guard global**: `JwtAuthGuard` dipasang sebagai `APP_GUARD`, jadi semua rute wajib login kecuali yang ditandai `@Public()` (hanya register, login, refresh, health).
- **Otorisasi / IDOR**: transaksi, jadwal, tugas pakai `findOwned(userId, id)` sebelum update/delete. Grup dan tagihan lewat `assertMember`. Hapus tagihan hanya pembuat. `mark-paid` hanya pemilik bagian, `confirm`/`reject` hanya pembayar. `scheduleId` di tugas dicek milik user sendiri. Payer dan peserta tagihan dicek anggota grup.
- **Input**: `ValidationPipe` dengan `whitelist` + `forbidNonWhitelisted` (mass assignment ditolak). Path param UUID divalidasi. Kursor divalidasi (UUID + tanggal ISO tahun 4 digit, BUG-04 benar sudah jadi 400). Raw SQL hanya pakai tagged template Prisma (`$queryRaw\`...\``) yang otomatis parameterized, tidak ada string concatenation.
- **Body limit** 100 kb, `x-powered-by` dimatikan, error 500 tidak membocorkan stack ke klien (hanya ke log server).
- **Rate limit** login dan register: `ThrottlerGuard` 10 percobaan / 60 detik per IP.
- **Rahasia**: tidak ada `.env` di repo, `.gitignore` menutup `.env` dan `.env.*`. Satu-satunya `EXPO_PUBLIC_*` adalah `EXPO_PUBLIC_API_URL` (bukan rahasia).
- **Mobile**: token di `expo-secure-store` (web preview hanya di memori, bukan localStorage). Tidak ada `console.log` di `src`. Param dari deep link/route di-`encodeURIComponent` sebelum masuk path API, dan otorisasi tetap di server. Logout tetap membersihkan token lokal walau server tidak bisa dihubungi. Refresh otomatis dibuat satu kali untuk request bersamaan, jadi tidak bentrok dengan rotasi sekali pakai.

## Dependensi

`npm audit --omit=dev` **tidak bisa dijalankan** di sesi ini (perintahnya butuh izin dan tidak ada yang bisa menyetujui). Jadi saya tidak punya hasil audit dependensi. Cek manual `package.json`: semua dependensi produksi versi terbaru dari jalur utamanya (NestJS 11, Prisma 6, bcryptjs 3, Expo SDK 58), tidak ada paket terlarang atau layanan berbayar. Indah atau Gilang perlu menjalankan `npm --prefix apps/backend audit --omit=dev` dan `npm --prefix apps/mobile audit --omit=dev` sekali sebelum rilis, lalu laporkan yang high/critical.

## Catatan untuk area orang lain

- Bagus (kontrak): kalau S2 dikerjakan, tambahkan respons `429 TOO_MANY_REQUESTS` di `POST /groups/join` dan `POST /auth/refresh` di `contracts/openapi.yaml`.
- Indah (DevOps): tambahkan langkah generate `JWT_ACCESS_SECRET` di `docs/cara-menjalankan.md` (terkait S1).
